# Роли и ответственность

| Роль | Ответственность |
|------|-----------------|
| **Стейхолдер** | Продуктовые решения, приемка анализа, приёмка PR/MR, доступы |
| **Оркестратор** | Процесс, все вызовы ролей и handoff, `status.md`, bootstrap, эскалации |
| **Аналитик** | Требования и AC для **новых фич** |
| **Архитектор** | Дизайн системы, границы, ADR |
| **Техлид** | Декомпозиция, задачи разработчикам, приёмка до QA |
| **Разработчик** | Реализация по задаче и стеку |
| **DevOps** | GitHub Actions, упаковка релизов и диагностика установки |
| **QA** | Тест-дизайн, прогоны .NET, ручные проверки в Jellyfin, вердикт |
| **Финализатор** | DoD, доки, PR/MR delivery, архив после acceptance |

Промпты ролей: [`.agents/skills/sdlc/role/`](../../.agents/skills/sdlc/role/).

## Взаимодействие

- Делегируйте роли как отдельные подзадачи; если субагенты недоступны, используйте ручной handoff по [навыку `sdlc`](../../.agents/skills/sdlc/SKILL.md).
- Оркестратор делегирует одну роль за раз (hub), ждёт отчёт, фиксирует handoff в `status.md` и только после этого запускает следующую роль. Другие роли не запускают субагентов: они возвращают результат Оркестратору.
- Аналитик ↔ Стейхолдер — уточнение «что».
- Аналитик → Оркестратор → Стейхолдер — обязательный gate после аналитики новой фичи: продолжать к Архитектору или оставить в backlog.
- Архитектор → Оркестратор → Аналитик — уточнение требований для дизайна.
- Техлид передаёт план Оркестратору. Оркестратор вызывает разработчиков и DevOps; их результаты передаёт Техлиду на ревью.
- Техлид → Оркестратор — handoff к QA после accept и DevOps impact check.
- DevOps ↔ Оркестратор — troubleshooting инфраструктуры, bootstrap, CI/runners, секреты и окружения (вне цикла реализации).
- DevOps ↔ Стейхолдер — продуктовые решения по доступам и секретам.
- QA → Оркестратор → Техлид — дефекты и доработка.
- Финализатор ↔ Оркестратор — PR/MR delivery, возврат rejected PR/MR, архив после acceptance.
