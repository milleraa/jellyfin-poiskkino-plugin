# Роли и ответственность

| Роль | Ответственность |
|------|-----------------|
| **Стейхолдер** | Продуктовые решения, приемка анализа, приёмка PR/MR, доступы |
| **Оркестратор** | Процесс, `status.md`, bootstrap, эскалации |
| **Аналитик** | Требования и AC для **новых фич** |
| **Архитектор** | Дизайн системы, границы, ADR |
| **Техлид** | Декомпозиция, задачи разработчикам, приёмка до QA |
| **Разработчик** | Реализация по задаче и стеку |
| **DevOps** | Docker, CI/CD, deploy scripts, Helm/Kubernetes, troubleshooting поставки |
| **QA** | Тест-дизайн, прогоны, Playwright, вердикт |
| **Финализатор** | DoD, доки, PR/MR delivery, архив после acceptance |

Промпты ролей: [`.opencode/agents/`](../../.opencode/agents/).

## Взаимодействие

- Все роли кроме Оркестратора вызываются как отдельные подзадачи/субагенты с ролевыми промптами из [`.opencode/agents/`](../../.opencode/agents/).
- Оркестратор делегирует одну роль за раз (hub), ждёт отчёт, фиксирует handoff в `status.md` и только после этого запускает следующую роль. Исключение: Техлид ведёт цикл `developer-*` / `devops` без Оркестратора между задачами.
- Аналитик ↔ Стейхолдер — уточнение «что».
- Аналитик → Оркестратор → Стейхолдер — обязательный gate после аналитики новой фичи: продолжать к Архитектору или оставить в backlog.
- Архитектор → Оркестратор → Аналитик — уточнение требований для дизайна.
- Техлид ↔ Разработчики/DevOps — задачи и ревью (внутренний цикл).
- Техлид → Оркестратор — handoff к QA после accept и DevOps impact check.
- DevOps ↔ Оркестратор — troubleshooting инфраструктуры, bootstrap, CI/runners, секреты и окружения (прямой вызов вне happy path фичи); в happy path — через Техлида.
- DevOps ↔ Стейхолдер — продуктовые решения по доступам и секретам.
- QA → Оркестратор → Техлид — дефекты и доработка.
- Финализатор ↔ Оркестратор — PR/MR delivery, возврат rejected PR/MR, архив после acceptance.
