# ADR-0002: Переход на Jellyfin 12.x и .NET 10 (plugin ABI)

## Статус

Accepted (реализация: ветка `feature/jellyfin-12-support`, issue #6)

## Контекст

- Jellyfin 12.0 (релиз 2026-09-08) перевёл сервер на .NET 10 и сменил plugin ABI. Плагин, собранный под `net9.0` и API 10.11.5, в 12.x не загружается: `PluginManager` вызывает `Assembly.GetTypes()` для проверки загрузки и при `TypeLoadException`/`ReflectionTypeLoadException` помечает плагин как `NotSupported` с сообщением «references an incompatible version of one of the shared libraries».
- Проверка `targetAbi` из `meta.json` к нашей поставке не относится: релизный архив не содержит `meta.json`, поэтому `PluginManager.LoadManifest` присваивает `TargetAbi = _appVersion` (версия сервера), то есть плагин считается совместимым по манифесту и отваливается именно на загрузке типов.
- Официальные NuGet-пакеты `Jellyfin.Controller` / `Jellyfin.Model` начиная с 12.0.0 поставляются только для `net10.0`.

## Решение

1. Оба проекта (`PoiskKinoMetadataPlugin`, `PoiskKinoMetadataPlugin.UnitTests`) переведены на `net10.0`.
2. Компиляция против **минимальной** поддерживаемой версии API — `Jellyfin.Controller` / `Jellyfin.Model` **12.0.0**, а не последней (12.4.0). Так ссылки на сборки Jellyfin не выше версии сервера, и один артефакт работает на всей линейке 12.x.
3. `Microsoft.Extensions.Http` — 10.0.11 (версия, согласованная с базовой зависимостью Jellyfin 12.0.0).
4. Версия релиза — по принятой в репозитории датной схеме (`v2026.11.22`), semver не вводим. ABI-разрыв фиксируется в release notes: релизы начиная с `v2026.11.22` — только Jellyfin 12.x, последний релиз для 10.11.x — `v2026.10.30`.
5. CI (`ci.yaml`, `release.yaml`) переведены на `dotnet-version: 10.0.x`.
6. Приёмка включает не только `dotnet test`, но и ABI-smoke: загрузка собранной DLL в процессе с `Jellyfin.Controller`/`Model` 12.0.0 и вызов `Assembly.GetTypes()` — воспроизводит проверку `PluginManager` без запуска сервера.

## Последствия

**Плюсы**

- Плагин загружается в Jellyfin 12.x; исходный код провайдеров менять не потребовалось (используемые интерфейсы `IRemoteMetadataProvider`, `IRemoteImageProvider`, `IExternalId`, `BasePlugin`, `IHasWebPages` в 12.0 не ломались).
- Один артефакт на всю линейку 12.x за счёт компиляции против 12.0.0.
- Проверяемая ABI-совместимость есть в локальном пайплайне, а не только «на сервере у пользователя».

**Минусы / риски**

- Релизы после `v2026.11.22` не работают на 10.11.x: для старой линейки остаётся отдельный релиз `v2026.10.30`.
- Компиляция против 12.0.0 не даёт пользоваться API, добавленным в 12.1–12.4; при необходимости такого API придётся поднимать baseline и сужать поддерживаемый диапазон.
- Полный smoke на живом Jellyfin 12 в CI не выполняется (нет инстанса); ABI-smoke покрывает загрузку типов, но не поведение провайдеров внутри сервера.

## Альтернативы

- **Компиляция против 12.4.0 (последняя)**: отвергнуто — не даёт новых нужных API, но рискует несовместимостью на серверах 12.0–12.3.
- **Мультитаргет `net9.0;net10.0` и два артефакта**: сейчас не нужно (10.11-линейка закрыта релизами 1.x); вернуться, если потребуется поддержка обеих линий одним релизным процессом.
- **Оставить 10.11 и ждать**: неприемлемо, плагин не работает на актуальной стабильной Jellyfin.
