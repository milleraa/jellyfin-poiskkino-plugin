# ADR-0003: Настраиваемый базовый URL внешнего API плагина

## Статус

Accepted (фича `eu-api-endpoint`, issue [#8](https://github.com/milleraa/jellyfin-poiskkino-plugin/issues/8); решения Стейхолдера Q1/Q2 на gate `analysis-review` 2026-11-27)

## Контекст

- Хост API ПоискКино был зашит константой `https://api.poiskkino.dev` в `PoiskKinoApiClient` и применялся один раз в конструкторе как `HttpClient.BaseAddress`; все запросы используют относительные пути `/v1.5/...`.
- Живая спецификация API объявляет второй базовый адрес `https://eu-api.poiskkino.dev` (`servers` в `api-docs/documentation.yaml`) и обслуживает те же методы тем же токеном. Серверы за пределами РФ не могут им воспользоваться без форка плагина.
- Стейхолдер выбрал: (Q1) свободное поле URL, а не whitelist из двух хостов; (Q2) перезапуск Jellyfin после смены хоста допустим.
- Клиент создаётся лениво один раз на провайдер (`Lazy<PoiskKinoApiClient>` в 5 провайдерах), поэтому место, где значение «захватывается», определяет, нужен ли перезапуск. При этом `BasePlugin<T>.UpdateConfiguration` обновляет конфигурацию в памяти сразу ([`BasePluginOfT.cs`](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.Common/Plugins/BasePluginOfT.cs)) — именно поэтому `ApiKey` действует «на лету», а base URL так действовать не обязан.
- Нужен воспроизводимый шаблон для будущих настраиваемых внешних адресов (третье зеркало, собственный шлюз), а не одноразовая правка константы.

## Решение

1. **Конфигурация.** Новое свойство `PluginConfiguration.ApiBaseUrl` (строка, инициализатор — дефолт `https://api.poiskkino.dev`). Имя свойства = элемент XML-схемы конфигурации; переименование в будущем = миграция. Отсутствующий в старом XML элемент оставляет инициализатор, миграции не требуется.
2. **Единая политика — чистый хелпер.** `ApiBaseUrlResolver` (internal static, без зависимостей от Jellyfin/HTTP) хранит константу дефолта и делает детерминированную нормализацию: trim; отсутствие схемы → `https://`; допускается только `https`; запрещены `userinfo`/`query`/`fragment`/непустой путь; удаляются завершающие `/`; порт разрешён. Невалидное значение → дефолт + причина, **без исключений**.
3. **Точка применения — конструктор клиента.** `PoiskKinoApiClient(IHttpClientFactory, ILogger, string? apiBaseUrl = null)`: клиент один раз резолвит значение и ставит `HttpClient.BaseAddress`. Провайдеры передают сырое значение из `Plugin.Instance.Configuration` по тому же паттерну, что и `ApiKey`; клиент не обращается к статическому синглтону.
4. **Корневой базовый URL.** Механизм склейки — `HttpClient.BaseAddress` + относительные пути с ведущим `/`; такой путь по правилам `System.Uri` заменяет путь базового адреса, поэтому base URL с подпутём отвергается с предупреждением, а не «молча теряется».
5. **Смена применяется после перезапуска.** Значение — construction-time параметр ленивого клиента; AC-7 (live-переключение) не реализуется по решению Стейхолдера (AC-7′), ограничение документируется в `README.md`.
6. **Диагностика.** `Information` с фактическим базовым URL при создании клиента; `Warning` с причиной при fallback. API-ключ не логируется никогда (резолвер его не получает). Нормализованное значение обратно в конфигурацию не записывается.

## Последствия

**Плюсы**

- Зеркало (и третье зеркало в будущем) выбирается настройкой, без пересборки плагина и без изменения схемы конфигурации.
- Дефолт сохраняет прежнее поведение; старые XML-конфигурации читаются без миграций.
- Политика нормализации изолирована и тестируется без моков; в клиенте остаётся только транспорт.
- Минимальный дифф: одно свойство конфигурации, один хелпер, один параметр конструктора, по одной строке в 5 провайдерах, поле в UI, тесты, документация. Ни новых пакетов, ни env-переменных, ни фоновых задач.

**Минусы / риски**

- Смена хоста требует перезапуска Jellyfin; до перезапуска возможен кратковременный «смешанный» набор хостов между лениво созданными клиентами провайдеров (сглаживается логом и документацией).
- Кэш 24 ч не содержит хост в ключе. При текущей restart-семантике это безопасно (клиент и кэш пересоздаются), но станет дефектом, если когда-нибудь будет реализовано live-переключение: тогда хост обязан войти в ключ кэша.
- Базовый URL с подпутём (корпоративный reverse proxy) не поддерживается — только корень хоста.
- Имя свойства фиксируется в XML-схеме конфигурации.

**Влияние на операции:** новых секретов, env-переменных, CI-шагов и исходящих хостов по умолчанию нет. Документация обязана содержать: оба известных хоста, требование перезапуска после смены, правила нормализации.

## Альтернативы

- **Whitelist из двух хостов (select в UI).** Отвергнуто Стейхолдером (Q1): третье зеркало потребовало бы релиза, а администратор с собственным шлюзом остался бы без варианта. Опечатки закрываются нормализацией/fallback с предупреждением, а не ограничением ввода.
- **Live-переключение без перезапуска (AC-7).** Технически возможно (конфигурация в памяти обновляется сразу), но требует абсолютных URI на каждый запрос вместо `BaseAddress`, потокобезопасного обновляемого резолва и хоста в ключе кэша — то есть заметно большего диффа и новых рисков ради UX, который Стейхолдер не потребовал (Q2).
- **Именованный `HttpClient` через `IHttpClientFactory`/DI.** Отвергнуто: провайдеры плагина создаются механизмом плагинов Jellyfin, DI-регистрации нет; конфигурация всё равно читалась бы на старте, то есть те же restart-семантики при большем плумбинге.
- **Нормализация в `Plugin.UpdateConfiguration` с записью канонического значения.** Отвергнуто: меняет поведение lifecycle-хука Jellyfin и «молча» переписывает конфигурацию существующих пользователей; сырое значение + лог фактического URL дают тот же эффект наблюдаемости.
- **Автовыбор/фейловер между хостами.** Вне scope (analysis OQ-2): скрытая смена географии запросов, неопределённая семантика суточного лимита между хостами, усложнение кэша; при появлении потребности — отдельная фича с отдельным ADR.
- **Диагностика `GET /v1.5/token` в UI.** Отложено как отдельная фича: браузерная проба измеряет сетевой путь браузера администратора, а не Jellyfin-сервера (диагностика вводит в заблуждение), корректный вариант требует серверного эндпоинта в плагине (новая HTTP-поверхность) и не тестируется в CI без реального ключа.
