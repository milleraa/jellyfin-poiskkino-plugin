# QA — `eu-api-endpoint`

## Известные ограничения (от Техлида, не блокируют прогон)

1. **Нет реального API-ключа (analysis R2 / architecture A7).** End-to-end поиск на `https://eu-api.poiskkino.dev` выполняется только администратором с ключом; автотесты фиксируют хост в `RequestUri`, а не сетевой ответ. Пробы без ключа — `401` на обоих хостах.
2. **Смена базового URL — только после перезапуска Jellyfin (AC-7′).** До рестарта 5 ленивых клиентов могут держать разные `BaseAddress` (A1) — это ожидаемое поведение, не дефект.
3. **Кэш не учитывает хост (analysis R7 / A3).** In-memory кэш 24 ч живёт в клиенте; после рестарта клиенты пересоздаются. Загрязнения между хостами в текущей семантике нет.
4. **Residual risk (принят Техлидом 2026-11-28): ключ, вставленный в поле «Базовый URL API».**
   - ключ как `userinfo` (`https://KEY@host`) — **безопасно**, в `Warning` остаётся `https://host` (фикс `bf2f6bc`);
   - ключ в query/fragment (`https://api.poiskkino.dev/?token=KEY`) — попадает в `Warning` как часть сырой строки (query не редактируется);
   - ключ как голое значение (`https://a1b2c3d4-e5f6-…`) — парсится как single-label host, попадает в `Information` как часть фактического адреса.
   Требуется, чтобы администратор сам вставил секрет не в то поле; `ApiKey` из конфигурации в лог не попадает (AC-9, тест `ApiKey_NeverAppearsInLogs`). При проверке логов на QA-стенде используйте только тестовый ключ/заглушки.
5. **UI (`configPage.html`) автотестов не имеет** — проверяется вручную по сценариям из [tasks/003](tasks/003-config-page-field.md). `datalist` можно удалить без влияния на поле, если в живом Jellyfin поведёт себя неожиданно.
6. **IPv6-литерал и base URL с подпутём** — отклоняются резолвером (fallback + `Warning`); подпуть документирован, IPv6 — нет.
