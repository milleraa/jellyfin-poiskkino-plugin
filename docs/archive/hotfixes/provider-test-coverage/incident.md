# Hotfix: покрытие поведения провайдеров

## Симптомы и доказательства

Точечный аудит на базе `b08b586` выявил два пробела. Намеренные поломки проверялись отдельно во временной копии; исходники затем восстановлены.

| Сценарий | Намеренная поломка | Результат |
|----------|--------------------|-----------|
| [Поиск сериалов по году](../../../../PoiskKinoMetadataPlugin.UnitTests/Providers/PoiskKinoSeriesProviderTests.cs#L89) | Убран вызов `SearchYearFilter.Apply` в провайдере сериалов | 28 из 28 тестов провайдера и фильтра прошли с поломкой и после восстановления |
| [Роли персон](../../../../PoiskKinoMetadataPlugin.UnitTests/Providers/PoiskKinoSeriesProviderTests.cs#L184) | Провайдер сериалов присваивает всем персонам `PersonKind.Actor` | 281 из 281 теста прошёл с поломкой и после восстановления |

## Влияние и временные меры

CI не обнаруживает проверенные регрессии. Сбой в продакшене не подтверждён, временные меры на сервере не требуются. Оформлено как hotfix по запросу Стейкхолдера без назначения P-приоритета.

## Критерии приёмки

- Через `GetSearchResults`: из двух сериалов с разными диапазонами `releaseYears` возвращается только подходящий по году; при отсутствии совпадений возвращаются оба. Правило: [ADR-0001](../../../architecture/decisions/ADR-0001-search-year-filter.md).
- Через `GetMetadata` фильмов и сериалов: проверить роли в `result.People`, включая случай, когда профессия задана только на английском. Заменить проверки приватного метода через рефлексию без потери сценариев.
- Повторить обе намеренные поломки в изолированной копии: новые тесты падают по ожидаемым утверждениям. После восстановления проходит полный `dotnet test`.
- Не менять поведение плагина, настройки, CI и упаковку.
